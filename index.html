Weight-space editing a prompt-injection classifier

Can a detector be improved by reading its internals and writing a few thousand weights by hand, with no gradient training? Partly. This is the full record, including what failed.

November 2026 · code and results · experiments run with Claude Code on Modal

Summary

  • Target: protectai/deberta-v3-base-prompt-injection-v2 (184M parameters). Method follows the idea in Weight-Space Programming: diagnose the network, then write weights directly.
  • Diagnosis: mid-network, the model separates benign prompts that merely contain trigger words from real injections. The last feed-forward block destroys most of that signal before the classifier reads it.
  • The final edit (v5) changes 15,363 weights (0.008%), all in the last layer and the head, set in closed form.
  • On new examples from the kinds of sources used in design: attacks caught 64.3% → 88.2%, false positives 2.3% → 1.8%.
  • On sources never used in design: attacks caught 66.3% → 67.1%, false positives 1.8% → 1.6%. Both move the right way, but the margin is thin.
  • Earlier versions looked much better than they were. Two of them were worse than simply moving the baseline's threshold once tested on fresh human-written data.

Setup

The classifier labels a prompt SAFE or INJECTION. All numbers use the model's default threshold of 0.5 unless stated. "TPR" is the share of attacks caught; "FPR" is the share of benign prompts wrongly flagged.

Edits were restricted to what the blog post's experiments allow: forward passes for diagnosis, then weights written from closed-form statistics (means, covariances, quantiles). No gradient steps, no training loop.

Data came from public Hugging Face datasets. Each stage kept a split that the edit never saw, and the last stage also kept whole sources unseen.

Diagnosis

The model knows the difference mid-stack and loses it by the end. A follow-up test located the loss: units reading the CLS state just before the last feed-forward block cut the trigger-word false-positive rate to about 15% in cross-validation, against 30% for units reading just after it.

The edit

Only the CLS output of the last layer is ever used, so the last layer can be reprogrammed without side effects on other tokens.

1. Free a wireOne residual coordinate (66) is cleared: nothing else writes to it, and a +/− unit pair cancels what it already carries.
2. Gated unitsFour feed-forward units read the pre-destruction CLS state. Two fire on missed attacks, two on wrongly flagged benign text.
3. Exact readoutA +/− pair in the pooler reads the wire linearly (gelu(z) − gelu(−z) = z) into the logit.
4. BiasThe classifier bias moves 3.79 logits toward SAFE, spending part of the gain on fewer false positives.

Each gated unit is gelu(s·(v·h − t)). The direction v is a shrunk, whitened difference of means between the examples it should fire on and those it must leave alone; the threshold t is a high quantile of the protected group, so the unit stays off for them. Units are added greedily, each one designed against the errors that remain. With no units firing, installing the wire moves any logit by at most 0.07.

The edit raised false positives on ordinary prompts ("What's the best book on gravitation?") and was beaten by a plain threshold change. v1 had also raised false positives on benign role-play prompts from 1.1% to 8.9%, which v2 fixed.

v3: false-positive units only

With only the two suppressing units, the edit cannot create false positives. On the five-dataset test split, false positives fell from 85 to 25 and NotInject FPR from 46.2% to 13.0%, losing 6 of 1,907 detections. On the human-written set it was neutral: 13 fewer false positives, 60 fewer attacks caught.

Looking for a signal that transfers

To check whether the edits were simply reading the wrong place, I scored linear readouts by leave-one-source-out: fit on three groups of sources, test on the fourth. The measure is attacks caught out of 3,629 at the baseline's own false-positive count.

There is a transferable signal of the form "some token strongly shows feature X", but it is spread over many features and needs a true max over tokens. Unwhitened difference-of-means directions also transferred far better than whitened ones, which is a mark against the directions used in the units above.

v6: building the one-head version

I reprogrammed one attention head in layer 11 to attend to the token with the largest projection, write that value to a second freed coordinate, and carry it to a linear reader in the last layer. The circuit works mechanically: the carried value correlates 0.85 with the intended max, and installing it flips 10 of 38,648 predictions. It adds almost nothing to detection: about 28 attacks over a threshold shift on its own, and slightly negative on top of the four units. v6 is not better than v5 and touches 234,357 weights.

Limitations

  • The never-seen margin is small. +32 attacks and −12 false positives out of 9,119. Of five bias settings tried, the reported one was the only one that improved both, and it was chosen with those results visible.
  • Leave-one-source-out was pessimistic. When a whole source is withheld from design, no setting of the four-unit edit beat the baseline on both metrics. The edit generalises to new examples from familiar sources much better than to new sources.
  • Ranking quality on never-seen sources dips (AUROC 97.3 → 96.8). The gain is at the 0.5 operating point.
  • Repeated looks. The five-dataset test split and the first human-written set were each consulted across several iterations and should be read as development data.
  • Label noise. deepset labels some plain role-play requests as attacks. The "regular" in-the-wild prompts contain real jailbreaks. One synthetic dataset (jayavibhav/prompt-injection) was dropped after inspection because its two classes were hard to tell apart by eye; the baseline flagged 82% of its "benign" rows.
  • Truncation. Inputs are cut at 512 tokens, so attacks late in long emails may be missed by any version.
  • Not tried: gradient fine-tuning on the same pool, which is the obvious comparison.

Takeaways

  • Reading the network before editing paid off: the finding that the last feed-forward block discards a useful distinction was specific and exploitable.
  • A handful of hand-written units can produce large gains on the distribution they were designed on. Those gains say little about new sources.
  • Always compare against the baseline at a matched false-positive count. Two versions here improved the headline rate while being worse than a threshold change.
  • Evaluate on whole sources that design never touched, and look at the rows: one dataset with an 82% "false-positive rate" turned out to be a labelling problem.

modal run wsp_v4.py --stage select       # leave-one-source-out

modal run wsp_probe.py --stage combo     # transferable-signal search
modal run wsp_v6.py                      # token-max circuit

The edit itself is in wsp_path.py (about 120 lines). Numeric results for every stage are in the results/ folder of the repository. Model weights are not published; the commands above rebuild them.
